## §3 设计

### S1 修复（红1-3 + 橙4-6）
- **胜负**：enterPhase 的 move:'point' 记 `duet.point`；approach 结束比**各自到 point 的实际距离**（位置单调趋近，先到者更近；双双到点由 separate 推开后距离近似相等 → 平局保持发起方，与旧 tie-break 一致）。世界到点分支对 busy 宠只清 target 不动档位。
- **合演独占**：idleChain 早退加 `a.busy`；到点分支 `if (!a.busy)` 才 play('idle')。合演期间的档位**只**由导演写。
- **手势/余额**：点击视觉反应跳过 busy 宠；好奇凑近的 mate 条件加 `!busy && !working && immune<=0`（worldGestures 收 minds）；余额播报跳过 held/busy。
- **bond 同步**：start() 持有 model 引用，帧循环里与 minds.bond 同步刷新；flush 回包 **无条件采纳** host 快照（reset 后 0/0 立即生效）；另加 30s 对账读。
- **关插件不丢账**：stop() 先 best-effort `fetch(PUT /bond, {keepalive:true})` 再清计时器。

### S2 会话跟随（F1）
- stimuli.js 闭包记 `focusId`：`ctx.on('api-session/activity')` → focusId = sessionId（最后被用户写消息的会话）。
- 所有 push 带 session 并**host 侧过滤**：来源会话（payload.agent.id / exec.agent.id）≠ focusId 的诱因一律不上板；focusId 为 null（host 重启后尚无用户消息）→ 全静默（这正是「跟随当前会话」的字面义；用户下一次发言即恢复）。
- 审批/提问 relay：载荷带 agent 就过滤，不带就放行（等待是用户必须看见的面）。
- board.push 增加 session 字段（/state 透出，留证）。

### S3 任务跟随（F2）
- KINDS += `task-start / task-progress / task-done`（contract + client 逐字镜像）。
- **待办**：pre-execute 里 `exec.name === 'todo_write'` → `exec.arguments.todos` → 签名去重（JSON 全量比对，重复调用不上板）→ 首见 task-start、done 数变化 task-progress（detail "3/7"）、全完成 task-done。
- **后台任务**：`ctx.get('jobs')` 探测（与 commands 同款优雅降级，不进 inject）→ subscribe({owners:'all'}) → 只认 owner === focusId：registered → task-start(label)、settled → task-done(label，cause 非 producer 加后缀)。
- client：主讲（workStatus ok 线）出气泡「接活了 / 3/7 / 收工！」；task-done 心情 +0.2。文案全原创。
